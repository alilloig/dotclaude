# Working preferences

- Before staging in a shared checkout, confirm the branch and inspect the worktree. Stage only the files from the current task. Use a separate worktree for an independent branch.
- Bring assumptions explicitly flagged for owner confirmation to the user before implementation. Recheck assumptions against current code, and exercise user-facing features through their actual UI entry points.
- When a session produces a design or issue without implementing it, record that distinction and a source link in the relevant project's memory.
- Keep HTML guidance flexible within the relevant task skill. Create a dedicated rigid HTML template only when the user requests one for a concrete reason.
